# Slip Scanner

A single-page Claude artifact for batch-filing invoices and till slips.

Scan on a phone or iPad (Adobe Scan works well), load the finished PDFs or photos, let Claude read the figures, check them, and file. Each approved invoice is:

1. renamed `YYYY-MM-DD_Supplier_InvoiceNo_R1234.56.pdf`,
2. placed in `Invoices_slip/YYYY-MM/` (or one flat folder, see Settings),
3. added to the receipt register (`RCT-2026-0001`, `RCT-2026-0002`, ...).

Downloads: a batch zip (PDFs in their `Invoices_slip` folders plus a CSV of the batch) and the full register as `.xlsx` or `.csv`.

## What it does

| Step | Detail |
| --- | --- |
| Import | Many PDFs and/or photos at once. A multi-page PDF can be split into one invoice per page. Photos are auto-cropped and enhanced (Original, Auto, Document, Black and white) with rotate. |
| Analyse | Claude reads each document (page images plus the PDF text layer) and returns supplier, invoice no, date, excl VAT, VAT, total, payment, card last four, category, notes and a confidence score. |
| Review | Every field is editable. Flags: missing supplier/total/date, excl VAT + VAT not equal to total, low confidence, possible duplicate (against the register and the batch). |
| File | Approved invoices get a register number, a standard file name and path, and a row in the register. |
| Register | Search, month and category filters, totals, a "Bank matched" tick per row, delete, import of an existing register (`.xlsx`/`.csv`, columns matched by name). |

The working queue is kept in the browser (IndexedDB), so reloading the page or switching to the camera does not lose scans. The register lives in the artifact's shared database when the `db` capability is available, otherwise in this browser.

## Publish it under another Claude account

The artifact is `src/slip-scanner.html`. In Claude, ask:

> Publish `src/slip-scanner.html` from this repo as an artifact with capabilities `db: {}`, `sample: {images: true}` and `downloads: true`.

Capabilities used:

| Capability | Why |
| --- | --- |
| `sample` with `images: true` | Claude reads the invoice images. Without it the Review tab still works by hand. |
| `db` | Register shared across devices and people. Without it the register is kept in this browser. |
| `downloads` | Saves the zip, xlsx and csv. Without it the page falls back to a normal browser download. |

Libraries load from cdnjs, pinned: pdf.js 3.11.174, pdf-lib 1.17.1, JSZip 3.10.1, SheetJS 0.18.5.

## Develop

- Change the register columns in `COLUMNS` and the import aliases in `ALIAS`.
- Default categories, entities, folder layout and number prefix are in `DEFAULTS` (also editable in Settings).
- File names and folders come from `fileBase` and `buildPath` (the pure functions at the top of the script).

## Tests

```
# logic tests (Node)
python3 test/build_pure.py && node --check test/_script.js && node test/pure.test.js

# end-to-end in headless Chromium (Python Playwright + Pillow)
LIBS=/path/to/unpacked/npm/packages python3 test/e2e_smoke.py
```

`LIBS` holds the unpacked npm packages `pdf-lib-1.17.1`, `jszip-3.10.1`, `xlsx-0.18.5` and `pdfjs-dist-3.11.174`. The e2e test serves them in place of cdnjs, fakes the `sample`, `downloads` capabilities, and runs: import a photo and a two-page PDF, split, edit, analyse, approve, file, download the zip and xlsx, reload.

`test/pure.test.js` expects `test/_pure.js`, generated by `test/build_pure.py`.

## Limits

- Photos are cropped automatically (no manual corner handles). For awkward photos, scan in Adobe Scan and import the PDF.
- HEIC photos are not read; export as JPEG or use the PDF.
- PDFs are previewed up to 30 pages each.
- The artifact cannot write straight into a folder on your computer. It hands you a zip to unzip into your banking folder.
